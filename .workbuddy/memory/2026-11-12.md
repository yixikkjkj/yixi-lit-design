# 2026-11-12 ld-input/ld-textarea minlength 校验修复（live() 指令）

## 问题与根因

yixi 反馈：ld-input 的 minlength 校验不生效，导致新密码字段只能继续用原生 input。

根因（CDP 真实输入探针实锤）：HTML 规范规定 `minlength`/`tooShort` 只对 dirty 标志（用户真实编辑过）的值生效，任何程序化 `input.value = x` 赋值都会清掉 dirty。LdInput 的链路是「用户键入 → onInput 写 this.value → 重渲染 → 模板 `.value=${this.value}` 写回内部 input」，每次键入都触发写回（哪怕值没变 setter 也执行），dirty 被静默清空，tooShort 永远 false。探针对照：纯原生真实键入 "abc" → tooShort:true；ld-input 同样键入 → false；原生 `n.value = n.value` 写回同值 → true 立刻变 false。

## 修复

- `src/components/input/index.ts`、`src/components/textarea/index.ts`：`.value=${this.value}` 改为 `live(this.value)`（lit/directives/live.js），值与 DOM 现值相等时跳过写回，仅外部真正改 value 时才同步
- `scripts/test-native-props.browser.js`：补回归断言（键入路径不得清掉内部 input 的 dirty/tooShort）

## 验证（CDP 真实键入）

- ld-input 键入 "abc"（minlength=8）→ tooShort:true + 完整校验消息 ✓（修复前 false）
- form.checkValidity() → false，内部 input tooShort:true ✓
- 清空后重键 "abcd" → tooShort:true ✓（二次编辑路径正常）
- 程序化赋值仍 tooShort:false，符合原生语义（minlength 本就只管用户编辑）
- 全部测试绿：native-props 45 项（含新断言）、tree-shaking、browser-build、formatter-lsp、typecheck、lint

## 排查手法沉淀

复现这类"程序化写回清 dirty"问题必须用 CDP Input.insertText 真实键入，`i.value='abc'; dispatchEvent(input)` 的模拟编辑不置 dirty 标志，会得出误导性结论（第一轮探针就被坑过）。

# 2026-11-12 CSS 按需改造 · 第三步（@layer 层叠层）

## 改动

- 新增 `src/styles/layers.css`：`@layer ld-tokens, ld-base, ld-components;` 单点声明层序
- `common.css` / `index.css` 首行引 layers.css（保证按需链与全量入口都先声明层序）
- 31 个样式文件包进对应层：tokens.css→ld-tokens，base.css→ld-base，其余 29 个（含 iconfont/remixicon.css）→ld-components
- `package.json` 新增 `./styles/layers.css` 显式 exports（`./styles/*.css` 通配指向 dist/components/*，不覆盖它）
- 新增 `scripts/test-cascade-layers.mjs` + `.browser.js`（真实 Chrome）：断言层序、消费方未分层样式胜出、多组件共存；npm 脚本 test:cascade-layers
- `test-tree-shaking.mjs` 补三层断言、两组件正反 import 顺序的层序断言、手工引 layers.css 的用例、consumer.ts 增 layers.css 导入
- `test-native-props.mjs` 修静默泄漏：Chrome profile 移出项目临时目录（原来 rm 删不掉但退出码 0，留下 6 个残留目录）
- README 新增「样式层叠顺序（@layer）」小节 + 特性条目 + 目录树；docs/index.html 只加 1 行说明（拒绝 oxfmt 对 HTML 的 1595 行重排，已回退后手工精修）

## 关键结论

- 全量包里 lightningcss 会**折叠独立的 @layer 声明语句**，层序退化为「块首次出现顺序」；实测产物顺序为 tokens(0) → base(15506) → components(16337)，仍正确。断言要按块位置判定，不能依赖声明语句存在。
- 消费端两种 import 顺序产出 CSS 长度相同但内部规则顺序不同（同一层内顺序随 import 变），所以**不能断言字节相等**，只能断言层序与「所有规则都在三个层内」。
- 收益：多组件按需引入与顺序无关；消费方未分层 CSS 天然优先（反向验证：剥掉层包裹后，同一测试的背景色从 rgb(1,2,3) 变成库的 rgb(0,82,217)）。
- 代价：浏览器基线 Chrome 99+/Safari 15.4+/Firefox 97+（2022 起），旧浏览器整段忽略层内规则，与 Lit 3 要求一致。
